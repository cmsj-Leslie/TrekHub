一、项目整体架构（回答："你的系统架构是怎样的？"）
================================================================================

1. 前后端分离的 B/S 架构
   - 前端：Vue 3 单页应用（SPA），通过 Axios 调用后端 RESTful API
   - 后端：Node.js + Express 提供 API 服务
   - 数据库：MySQL 8.0 关系型数据库，16张核心表
   - 两者通过 JSON 格式通信，JWT Token 做身份认证

2. 为什么选择前后端分离？
   - 前后端独立开发部署，职责清晰
   - 前端 SPA 用户体验好（无刷新切换页面）
   - 后端 API 可复用，将来可对接移动端

3. 代码位置：
   - 前端入口：frontend/src/main.js
   - 后端入口：backend/server.js
   - 数据库连接：backend/src/config/db.js

【创新点1】AI 大语言模型集成 — DeepSeek 智能助手
------------------------------------------------------------------------
  ★ 这是本项目最大的创新点，区别于传统 CRUD 系统

  创新描述：
  - 接入 DeepSeek 大语言模型 API，实现三种场景的 AI 对话：
    ① 线路规划助手：根据用户体能等级、偏好地区给出线路建议
    ② 组队匹配助手：分析用户需求推荐队友条件
    ③ 通用问答助手：解答徒步相关问题
  - 实现上下文多轮对话记忆（每个用户独立会话）
  - AI 智能线路推荐（根据用户画像从候选线路中筛选最适合的）

  关键技术：
  - 使用 OpenAI 兼容的 Chat Completions API 接口
  - System Prompt 工程：为三种场景设计不同的系统提示词
  - 上下文窗口管理：保留最近6条消息（3轮对话），平衡效果和成本

  Token 节省策略（可回答"如何控制 API 调用成本"）：
  - 上下文截断：只保留最近6条消息
  - 输出限制：max_tokens 限制为 300
  - 结果缓存：推荐结果缓存30分钟，相同请求不重复调用
  - 分类会话：三种场景独立管理，互不干扰

  代码位置：
  - AI 服务核心逻辑：backend/src/services/aiService.js（116行）
    → chat() 函数：对话式 AI，带上下文记忆
    → generateRecommendations() 函数：AI 批量推荐
    → callDeepSeek() 函数：底层 API 调用封装
  - AI 配置参数：backend/src/config/ai.js
  - AI 控制器：backend/src/controllers/aiController.js
  - AI 路由：backend/src/routes/ai.js
  - 前端 AI 页面：frontend/src/pages/AI/AIChat.vue


【创新点2】混合推荐算法 — 个性化线路推荐
------------------------------------------------------------------------
  ★ 区别于简单的按热度排序，实现了真正的个性化推荐

  算法公式：
    推荐分数 = 0.4 × 内容相关度 + 0.4 × 协同过滤相似度 + 0.2 × 热度权重

  三个维度详解：
  ① 内容相关推荐（Content-Based，权重40%）：
     - 根据用户等级（1-5级），推荐难度在 ±1 范围内的线路
     - 按收藏数排序
     - 例：3级用户 → 推荐难度2-4的线路

  ② 协同过滤推荐（Collaborative Filtering，权重40%）：
     - 找出与当前用户"行为相似"的用户（收藏了相同线路的人）
     - 推荐相似用户收藏但当前用户未收藏的线路
     - 相似度计算：共同收藏数 / 当前用户总收藏数
     - 这是推荐系统中经典的"User-Based CF"算法

  ③ 热度加权（Popularity，权重20%）：
     - hotness = (浏览量 × 0.3 + 收藏数 × 0.5) / 1000
     - 确保冷门但高质量的线路也有机会被推荐

  代码位置：
  - 推荐服务：backend/src/services/recommendService.js（118行）
    → getRecommendedRoutes() 主函数
    → getCollaborativeRoutes() 协同过滤实现
    → calcScore() 综合得分计算
  - 前端调用：frontend/src/pages/Home.vue 首页"为你推荐"板块


【创新点3】即时匹配的随机组队系统
------------------------------------------------------------------------

  创新描述：
  - 用户加入匹配池后立即触发一次匹配（不是等待定时任务）
  - 同时保留每1分钟定时任务兜底，确保不遗漏
  - 匹配成功自动创建活动 + 群聊 + WebSocket 实时通知

  匹配算法：
  - 日期兼容性检查：双方日期相同或未填
  - 技能标签交集检查：至少有1个共同技能
  - 最多6人一组

  技术亮点：
  - 匹配结果通过 WebSocket 即时推送到客户端
  - 使用数据库事务（Transaction）保证原子性：创建活动→创建群聊→添加成员→退出匹配池

  代码位置：
  - 匹配服务：backend/src/services/matchService.js（117行）
    → runMatching() 核心匹配逻辑
    → isCompatible() 兼容性判断
    → createMatchedActivity() 创建活动和群聊（事务操作）
  - 即时触发：backend/src/controllers/matchController.js
    → join() 方法中异步调用 matchService.runMatching()
  - 定时兜底：backend/server.js（cron.schedule 每1分钟）
  - 前端页面：frontend/src/pages/Match.vue

三、关键技术点（回答技术问题时用）
================================================================================

1. JWT 身份认证流程
   - 登录时：服务端验证用户名密码 → 用 jsonwebtoken 生成 Token → 返回给前端
   - 请求时：前端 Axios 拦截器自动从 localStorage 取 Token → 注入请求头
   - 验证时：后端 auth 中间件从 Authorization 头提取 Token → jwt.verify 解码
   - 代码位置：
     → 登录签发：backend/src/controllers/authController.js
     → 认证中间件：backend/src/middleware/auth.js
     → 前端拦截器：frontend/src/api/request.js

2. Sequelize ORM（为什么不写原生 SQL）
   - 对象关系映射，用 JavaScript 对象操作数据库
   - 自动防 SQL 注入（参数化查询）
   - 模型关联（hasMany、belongsTo）自动处理表关联
   - 事务支持（Transaction），保证数据一致性
   - 代码位置：backend/src/models/ 目录下所有文件

3. Vue 3 Composition API（为什么不用 Options API）
   - 逻辑复用：通过 composable 函数封装通用逻辑（useMap、useFavorite）
   - 代码组织：按功能而非选项聚合代码，可读性更好
   - TypeScript 友好（虽然本项目用 JS）
   - <script setup> 语法糖减少样板代码

4. Pinia 状态管理
   - 管理全局状态：用户登录信息、聊天数据
   - 替代 Vuex，更轻量、更好用
   - 代码位置：frontend/src/stores/user.js、frontend/src/stores/chat.js

5. 数据库事务（Transaction）
   - 随机组队时：创建活动 → 创建群聊 → 添加成员 → 退出匹配池
   - 这4步必须全部成功或全部回滚，保证数据一致性
   - 代码位置：backend/src/services/matchService.js createMatchedActivity()

6. CORS 跨域配置
   - 前端 localhost:5173 和后端 localhost:3000 属于不同源
   - 后端用 cors 中间件配置允许的前端地址
   - WebSocket 也配置了 CORS
   - 代码位置：backend/server.js

7. 文件上传（Multer 中间件）
   - 支持头像、评论图片、打卡图片上传
   - 限制文件类型和大小
   - 存储到 backend/uploads/ 目录
   - 通过 express.static 提供静态访问

五、可能的答辩提问与回答要点
================================================================================

Q1: 你的 AI 助手和普通 ChatGPT 有什么区别？
A: 我的 AI 助手专注于徒步领域，通过定制的 System Prompt 限定回答范围；
   分三种独立场景（线路规划/组队/通用），各自维护对话上下文；
   还结合平台数据做智能线路推荐，不是简单的聊天接口。

Q2: 推荐算法为什么用混合推荐而不是单一算法？
A: 单一算法有缺陷：
   - 纯内容推荐有"信息茧房"问题
   - 纯协同过滤有"冷启动"问题（新用户没有行为数据）
   - 纯热度推荐没有个性化
   混合推荐取长补短，效果更好。本项目用 4:4:2 的权重比例平衡三者。

Q3: WebSocket 和普通 HTTP 有什么区别？为什么聊天要用 WebSocket？
A: HTTP 是请求-响应模式，客户端不请求就收不到数据；
   WebSocket 是全双工长连接，服务端可以主动推送消息；
   聊天场景需要实时性，用 HTTP 轮询延迟大且浪费资源，WebSocket 更高效。

Q4: JWT 和传统 Session 认证有什么区别？
A: Session 需要服务端存储会话状态，有状态的；
   JWT 是无状态的，Token 自包含用户信息，服务端不需要存储；
   适合前后端分离架构，且天然支持分布式部署。

Q5: 你的系统安全性怎么保障的？
A: 六个方面：
   ① 密码 bcrypt 加密（不可逆哈希）
   ② JWT Token 认证
   ③ ORM 参数化查询防 SQL 注入
   ④ CORS 白名单
   ⑤ WebSocket 连接前 JWT 验证
   ⑥ 文件上传类型和大小限制

Q6: 如果匹配池人很多，匹配算法效率怎样？
A: 当前是 O(n²) 的遍历匹配，适合小规模用户；
   如果用户量大可以优化：按线路/日期分桶后局部匹配，复杂度降为 O(n)。

Q7: 你的项目和市面上的徒步 App（如两步路）有什么区别？
A: 本项目侧重社交和智能化：
   ① AI 助手可以对话式规划线路（两步路没有）
   ② 随机组队匹配系统（类似游戏匹配机制）
   ③ 混合推荐算法个性化推荐（不只是按热度排序）
   ④ 活动互评系统（帮助用户选择可靠队友）
